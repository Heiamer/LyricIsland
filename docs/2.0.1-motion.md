# 2.0.1 · 灵动岛动画的两条曲线

这一版只做一件事：给灵动岛的形变换一条更利落的曲线，同时把旧的那条完整留下。

## 开关在哪

**设置 · 外观与动画 · 灵动岛流体动画**（默认开启）。

- **开** → 2.0.1 的流体曲线。
- **关** → 逐帧回到 2.0.0 的原始曲线，参数、时序、缓动全部不变。

它和上方的「界面动画」是两个不同的开关：

| 开关 | 管什么 |
| --- | --- |
| 界面动画 | 动画本身开不开。关掉就全部瞬移，不看曲线。 |
| 灵动岛流体动画 | 动画用哪条曲线。只在「界面动画」开着时有意义。 |

两者都关时，灵动岛瞬间切换，与本项无关。

## 旧曲线（Classic）

2.0.0 的实现，代码路径保留在 `motion.rs` 的 `Style::Classic`，`Transition::new` 仍然是它。

八条弹簧并行推进八个通道，各带一个速度倍率：

| 通道 | 速度倍率 |
| --- | --- |
| 轮廓 `card_reveal` | 1.0 |
| 卡片不透明度 `card_opacity` | 1.5 |
| 模糊 `card_blur` | 1.2 |
| 内容不透明度 `content_opacity` | 1.3 |
| 缩放 `card_scale` | 1.5 |

展开总时长 640 ms，收起 533 ms。默认弹簧阻尼比约 0.82，略欠阻尼，因此轮廓会轻微过冲（钳在 1.035）再收回。

实测前 80 ms：轮廓走到 0.614，不透明度已经 0.851，内容 0.773。也就是说卡片还没张开到三分之二，里面的字已经基本看得见了——视觉上像界面在追赶自己的文字。这是这条曲线被换掉的原因，也是它被保留的原因：有些人就喜欢这种更松散、更有层次的读感。

## 新曲线（Fluid）

一条主弹簧推进轮廓，其余七个通道从它推导：

```text
p         = 主弹簧(0 → 1)         临界阻尼
fade      = smoothstep(p, 0.18, 0.74)   卡片层不透明度
content   = smoothstep(p, 0.44, 0.97)   内容不透明度
scale     = 0.96 → 1.00  在 p ∈ [0, 0.62] 内完成
blur      = 6 → 0        在 p ∈ [0.06, 0.70] 内完成
offset    = -18 → 0      线性跟随 p
```

因为所有通道读的是同一个 `p`，它们不可能互相脱节；中途反向时也一起反向。

关键取舍：

- **临界阻尼**（阻尼比下限 1.0）。点击展开没有惯性输入，过冲会读作界面在自作主张。用户的「弹簧阻尼」滑杆仍然有效：调到 1.0 以上会让落定更沉。
- **速度 1.32×**。展开 640 ms → 397 ms，收起 533 ms → 331 ms。仍在抽屉类界面的 500 ms 预算内，也接近其余界面的 300 ms 标准。
- **缩放起点 0.96**，不是 0。真实世界里没有东西从「什么都没有」里出现。
- **容器先于内容**。`content` 在 `p = 0.44` 才开始起量，此时轮廓已经过半，内容是长在容器里的，不是浮在上面的。

实测前 80 ms：轮廓 0.696，内容 0.474。文字开始出现时，容器已经给了它位置。

## 同一开关下的另外两处

拖动切换和淡入淡出也归这个开关管，因为它们的改动同样会改变手感：

- **轻扫判定**：位移 ≥ 42 px 或速度 ≥ 340 px/s 都算切换。旧版只看位移，快速一甩会弹回原位。
- **边界阻尼**：拖过自身宽度后按 `(over·w·0.55)/(w + 0.55·over)` 抵抗，不再硬钳。硬钳在手指还在动时突然停住，读作卡死。
- **淡入曲线**：`1 - (1-t)³`（ease-out）替代 `(1 - cos(πt))/2`（对称正弦）。对称正弦起手慢，而正在出现的界面正是眼睛盯得最紧的一刻。

## 不随开关变化的部分

- 反向中断：两条曲线都从当前屏幕值重新起算，并把速度交给新过渡。这是 2.0.0 就有的，没有被改动。
- `prefers-reduced-motion` 等价路径：`reduced` 分支仍是 120 ms 纯透明度过渡，两条曲线共用。
- 布局、命中测试、窗口尺寸：`Layout::shape` 与 `music_geometry` 未改动，两条曲线落到同一个终点帧（`Frame::expanded()` / `Frame::hidden()`），因此绘制与点击永远对得上。

## 设置窗口

设置窗口走的是另一套代码（GPUI，`lyric-settings/src/motion.rs`），它的弹簧从一开始就是按 `apple-design` 写的：阻尼比 + response 两个参数，`standard 1.0/0.34`、`snappy 1.0/0.24`、`sheet 0.82/0.36`。这一版只修了三处真正不对的地方，没有重调那些已经对的数值。

**页面级联的预算。** `cascade()` 原来每行 260 ms、错开上限 6 步，最后一行要等 392 ms。问题在于切换「常规 / 外观与动画 / 音效」会重放整段级联（`pulse()` 会 bump `content_epoch`），而分页是每次用设置都要点几十下的动作——按技能里的频率表，这个量级只配「几乎察觉不到」。改成 200 ms、位移 8 px、上限 4 步，最后一行 288 ms，仍在 300 ms 的天花板内，级联还在，只是不再像在等。

**勾选行的指针反馈。** `check_row`（通知页的应用勾选）原来自己写 `.hover()` / `.active()`，是瞬时切换；而紧挨着的开关行走 `live_shell` + `row_wash`，是弹簧。同一页两种手感，读起来像两套界面。现在勾选行也走 `live_shell`，左侧绿色指示条和底色一起弹出。

**遮罩不该有回弹。** 抽屉的遮罩和面板原本共用 `sheet()`（0.82 阻尼，带一点回弹）。遮罩不是「一个东西从边缘飞进来」，是「房间变暗」——过冲对透明度没有意义（`alpha()` 会把它钳掉），而且它应该比面板先落定。新增 `scrim()` = `1.0 / 0.22`：临界阻尼、更快，面板到位时背后已经暗下来。

**入场缓动对齐。** `ease_out` 从 `cubic-bezier(0.22, 1, 0.36, 1)` 改成技能里给出的 `cubic-bezier(0.23, 1, 0.32, 1)`。差别很小，但模块开头写着「following the bundled apple-design skill」，那就该是那个值。

### 没有改的部分

- 主题切换 260 ms `ease_in_out`：原地变色，本来就是 ease-in-out 的场合，正确。
- 悬停 / 按压的 `snappy()` 115 ms：技能里按压反馈是 100–160 ms，正确。
- 侧栏选中 `standard()` 160 ms：导航，属于「tens/day」，正确。
- 状态点呼吸 1400 ms / 30 fps：窗口里唯一的循环动画，连接成功即停，符合「只在对的地方循环」。
- 各处小按钮的 `.active(opacity)`：按压反馈本来就该是瞬时的，改它不是优化。

## 验证

`motion.rs` 里新增 6 个断言，覆盖：终点一致、单调不过冲、内容滞后于轮廓、中途反向不跳变、落定快于旧曲线、边界阻尼单调递增。

```text
cargo test -p lyric-native
cargo check -p lyric-settings
```
